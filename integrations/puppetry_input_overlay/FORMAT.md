# Puppetry input overlay: interface reference

Everything afterglow can rely on. Nothing here requires importing Puppetry
code; `afterglow_input_overlay.py` wraps it for convenience.

## Files (all in `$XDG_RUNTIME_DIR/puppetry/`, a per-user tmpfs, i.e. RAM)

| File | Written by | Purpose |
|---|---|---|
| `input_buffer.jsonl` | overlay helper | Rolling record of input, replay-buffer length + margin |
| `overlay_status.json` | overlay helper | Whether it's running, the buffer length and where it came from |
| `events.sock` | daemon | Live event stream (the helper's input; not needed by afterglow) |

If `XDG_RUNTIME_DIR` is unset, both live in `~/.config/macro-daemon/` instead.
Both files are mode 0600.

### `input_buffer.jsonl`

One JSON object per line. Line 1 is a header; every other line is an event,
oldest first.

```json
{"format": "puppetry-input-buffer", "version": 1, "clock": "unix",
 "start": 1790748471.090639, "length_s": 60.0, "held_at_start": {"KEY_LEFTSHIFT": 1790748470.51}}
{"t": 1790748508.395350, "e": "kd", "k": "KEY_LEFTCTRL", "s": "r"}
{"t": 1790748508.401233, "e": "mv", "dx": 12, "dy": -3, "s": "r"}
{"t": 1790748508.512000, "e": "wh", "n": 1, "h": 0, "s": "r"}
{"t": 1790748508.600102, "e": "ku", "k": "KEY_LEFTCTRL", "s": "r"}
{"t": 1790748508.700000, "e": "ax", "a": "LX", "v": -0.53, "s": "r"}
```

- `t`: Unix seconds (float, microsecond precision). For real input this is
  the kernel's own evdev timestamp (CLOCK_REALTIME), not the time Puppetry
  read the event.
- `e`: `kd` key/button down, `ku` up, `mv` relative mouse motion, `wh` wheel,
  `ax` game-controller axis.
- `k`: `KEY_*` / `BTN_*` name. Mouse buttons are `BTN_LEFT`, `BTN_RIGHT`,
  `BTN_MIDDLE`, `BTN_SIDE` and `BTN_EXTRA`. Controller buttons are named by
  position: `BTN_SOUTH` (A / Cross), `BTN_EAST`, `BTN_WEST`, `BTN_NORTH`,
  `BTN_TL`/`BTN_TR` (bumpers), `BTN_TL2`/`BTN_TR2`, `BTN_SELECT`,
  `BTN_START`, `BTN_MODE`, `BTN_THUMBL`/`BTN_THUMBR` and
  `BTN_DPAD_UP/DOWN/LEFT/RIGHT`. Unknown codes appear as `CODE_<n>`.
- `a`, `v` (controller axes): `LX LY RX RY` are sticks, -1..1, with right
  and down positive. `LT RT` are triggers, 0..1. `DPAD_X DPAD_Y` are -1, 0
  or 1. Thinned to about 125 Hz per axis, always ending on the latest value.
- `dx`, `dy`: raw device counts (before pointer acceleration), summed into
  roughly 8 ms steps.
- `n`, `h`: vertical (+ = up) and horizontal wheel notches.
- `s`: `r` real input (drawn in the input color, orange by default), `m`
  output generated by a Puppetry macro (drawn in the output color, blue).
- Header `start`: the earliest time the file is complete from. Events before
  it are gone; `held_at_start` lists keys that were already down at `start`
  (with their press times), so a render can show them held.
- Header `length_s`: the replay-buffer length the helper is currently
  keeping (from OBS, or Puppetry's fallback setting). The file actually
  holds `length_s + margin` (margin default 5 s) and up to ~5 s more
  between compactions.

Writing behaviour:
- New events are appended and flushed every 100 ms.
- About every 5 s the file is rewritten to a temp file and renamed over the
  original (atomic). A reader that already opened the old file keeps a
  consistent copy.
- A final line without a trailing newline is still being written. Skip it.
- Autorepeat is not recorded (only real down/up transitions).

### `overlay_status.json`

```json
{"pid": 1014, "updated": 1790748510.09, "daemon_connected": true,
 "pages": {"full": "http://127.0.0.1:17380/"},
 "replay": {"enabled": true, "file": "/run/user/1000/puppetry/input_buffer.jsonl",
            "length_s": 60.0, "length_source": "obs", "extra_s": 5.0},
 "obs": "connected; replay buffer 60 s"}
```

Rewritten about every 2 s. If `updated` is more than about 10 s old, the
helper is not running. `length_source` is `obs` when OBS reported its
replay-buffer length over obs-websocket (polled every 30 s), or `fallback`
when the setting in Puppetry was used.

## Command: `puppetry-overlay`

Installed with Puppetry (NixOS: `/run/current-system/sw/bin/puppetry-overlay`).
Every subcommand prints exactly one JSON object on stdout. On failure it
prints `{"error": "..."}` and exits 1. Times are Unix seconds.

| Command | Result |
|---|---|
| `status` | the contents of `overlay_status.json` |
| `snapshot OUT [--buffer F]` | `{"out": OUT}`: a copy of the live buffer, frozen |
| `render --start T --end T OUT [--buffer F] [--mode M] [--fps N] [--scale S] [--offset-ms MS]` | `{"out", "width", "height", "frames", "seconds", "coverage"}`: a transparent video of one piece |
| `align --overlay OV --overlay-start T --clip IN --clip-end T OUT` | `{"out", "skip_s"}`: OV cut to start with the clip and last as long (stream copy, frame-exact) |
| `layer --clip IN --piece FILE:X:Y:W [--piece ...] OUT [--clip-end T --overlay-start T] [--crf N]` | `{"out", "pieces", "overlay_skip_s"}`: pieces burned in at their placements |
| `composite --clip IN (--clip-end T \| --start T) OUT [--buffer F] [--mode M] [--position P] [--scale-frac F] [--margin PX] [--offset-ms MS] [--crf N]` | `{"out", "start", "end", "fps", "seconds", "coverage"}`: one piece, one pass |
| `apply --clip IN --overlay OV OUT [--clip-end T --overlay-start T] [--position P] [--scale-frac F] [--margin PX] [--crf N]` | `{"out", "overlay_skip_s"}` |
| `add-to-obs` | `{"sources": [[name, "created"\|"updated"], ...]}` |
| `obs-replay-length` | `{"seconds": 60.0}` |

Options:
- `--mode` (the pieces):
  - `full`: keyboard + mouse + movement arrow in one picture.
  - `keyboard`: the keyboard only.
  - `mouse`: the mouse + movement arrow only.
  - `controller`: a gamepad, with sticks that move, triggers that fill,
    bumpers, d-pad, and face buttons labelled Xbox / PlayStation / Nintendo
    per Puppetry's setting.
  - `simple`: one line of text of what's held.
  - `movement`: the movement arrow alone. This mode was called `mouse`
    before the pieces were split.
- `--piece FILE:X:Y:W`: X and Y are the top-left corner and W the width, all
  fractions of the clip (0 to 1). Height follows the piece's aspect ratio.
  Repeat the option for several pieces; later ones are drawn on top.
- `--position` (composite/apply): `top-left`, `top-center`, `top-right`,
  `bottom-left`, `bottom-center`, `bottom-right`, `center`.
- `--scale-frac` (composite/apply): the overlay's width as a fraction of the
  clip's width (default 0.35). `composite` draws directly at that size.
- `--offset-ms`: shifts the input timeline. Positive values show inputs
  later. Use it to calibrate against the video.
- `render` output must be `.mov` (qtrle, argb), `.mkv` (FFV1, yuva420p) or
  `.webm` (VP9, yuva420p). Anything else is refused.
- `composite`/`apply`/`layer` output: `.mp4`/`.mkv`/`.mov` get H.264 (`-crf`,
  preset veryfast). Audio is copied unchanged.
- `coverage`: `full` when the buffer reaches back to the clip's start,
  `partial` when it doesn't. A partial render still works; earlier inputs
  are simply absent.
- Look (colors, key size, timers, arrow, fonts, controller labels) comes
  from Puppetry's `~/.config/macro-daemon/overlay.json`, the same settings
  as the OBS pages.

### Transparency

Every piece is drawn on a fully transparent background (alpha 0 wherever
there's no key, button or arrow), and keys are slightly translucent by
default. Formats:

| Format | Alpha when decoded | Size (10 s, heavy activity) | Decode | Notes |
|---|---|---|---|---|
| `.mov` qtrle (**use this**) | yes, with ffmpeg/mpv defaults | ~10 MB | fastest | all-intra: `align` cuts are frame-exact |
| `.mkv` FFV1 | yes | similar | fast | |
| `.webm` VP9 | **only** with the libvpx decoder (`-c:v libvpx-vp9` before `-i`, mpv `--vd=libvpx-vp9`); ffmpeg's default VP9 decoder silently drops it | ~0.5 MB | fast | slow to encode (about 4x qtrle) |

Measured in the sandbox, not on the target machine. Controller-only and
simple pieces are much smaller.

## Sidecar folder (made by `afterglow_input_overlay.finish_clip`)

    clip.mp4
    clip.mp4.input/
        manifest.json
        inputs.jsonl          the frozen input for this clip (re-render any piece from it)
        keyboard.mov          one transparent qtrle file per piece, cut to the clip exactly
        mouse.mov
        controller.mov

`manifest.json`:

```json
{"format": "puppetry-overlay-sidecar", "version": 1, "clip": "clip.mp4",
 "clip_end": 1790748512.3, "offset_ms": 0, "visible_by_default": true, "inputs": "inputs.jsonl",
 "pieces": {"keyboard": {"file": "keyboard.mov", "width": 1076, "height": 320,
                         "placement": {"x": 0.02, "y": 0.76, "w": 0.34, "visible": true}}},
 "errors": {}}
```

Placements are fractions of the video, so they survive re-encodes and
resolution changes. A new clip's placements come from afterglow's defaults:
clip type (per piece) over global over the built-in table
(`resolve_placements`). After that only the editor changes them; the
previewer just toggles the whole overlay.

### Showing it in mpv (previewer / editor)

`preview_overlay_args(sidecar, video_w, video_h, enabled)` (previewer: on/off
at the saved placements) and `mpv_overlay_args(sidecar, placements, video_w,
video_h, enabled)` (editor: live placements) both return `(files, graph)`:

- set mpv's `external-files` to `files` when the clip loads (each becomes
  `vid2`, `vid3`, ... in the order given);
- set `lavfi-complex` to `graph`, and set it again after every toggle,
  move or resize. It is `[vid1] null [vo]` when the overlay is off or every
  piece is hidden.

Example graph (two pieces):

    [vid2] scale=640:190 [s1]; [vid1][s1] overlay=x=64:y=36:format=auto:eof_action=pass [o1];
    [vid3] scale=128:162 [s2]; [o1][s2] overlay=x=1126:y=475:format=auto:eof_action=pass [vo]

Reassigning `lavfi-complex` makes mpv rebuild its filter graph, which can
hitch playback for a moment. The recommended editor interaction is
therefore to drag a Qt outline over the video and update the graph on
release. (Not verified with mpv here: the same graph was checked by running
it through ffmpeg.)

## Timing model

A replay-buffer clip ends at about the moment OBS was told to save, so:

    clip_start = clip_end - clip_duration      (duration read from the file with ffprobe)
    clip_end   ~ time.time() when SaveReplayBuffer was sent

Encoder latency can put the real end a few frames earlier. `--offset-ms`
corrects a consistent error. Calibration: press a key that makes something
change on screen, save a clip, and compare the frame where the overlay key
lights up with the frame where the on-screen change appears. The difference,
in ms, is the offset (positive when the overlay is early).
